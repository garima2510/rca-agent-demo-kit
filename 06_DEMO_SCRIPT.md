# Demo script - "From P1 incident to draft RCA by the next morning"

## The story
Tue 4 Nov 2026, 03:10 - P1 INC0019874: splay/silver streaks and brittle CVR-115 covers on Eindhoven Line 2, ~20k parts quarantined, customer delivery Fri 6 Nov at risk.

**Ground truth the agent should find (planted in the data):**
| Evidence | Source | Value |
|---|---|---|
| Dryer DRY-EIN-L2-01 dew point rising from 31 Oct 06:00 | Genie Maintenance | -42 C -> ~-16 C by 3-4 Nov; first above -30 C on 1 Nov |
| Dryer PM deferred (no desiccant cartridge in stock) | Genie Maintenance | Preventive WOs on DRY-EIN-L2-01 since mid-Oct = Deferred |
| Defect rate EIN L2 | Genie Quality | ~1.2% baseline -> 4.8% (1 Nov) -> 10% -> 15.6% -> 18.9% (4 Nov) |
| New resin lot L-PC-26-1187 (Polymerix) from 31 Oct, moisture 0.046% (spec 0.02) | Genie Quality | dim_material_lot |
| Ruled out: barrel temp, cycle time, mould temp normal | Genie Maintenance | |
| No alarm at -29 C (1 Nov night); OEM default -20 C alarm only from ~3 Nov 05:00, acknowledged repeatedly | Shift log | communications |
| Same failure mode in Brno 2025 | RCA-2025-014 | desiccant saturation |
| Same supplier wet-lot issue in Valencia | RCA-2026-007 | no CoA moisture check |
| CAPAs not rolled out to EIN (alarm -30 C/interlock, critical spares, CoA check) | LL-2025-06, RCA-2025-014 CAPA #5, RCA-2026-007 CAPA #3 | **process gap** |

Expected conclusion: **root cause** = saturated dryer desiccant (PM deferred, no spare) -> insufficient drying; **contributing** = wet incoming lot 1187 with no CoA moisture check at EIN; alarm threshold at OEM default with no interlock; lessons learned from BRN/VAL not implemented at EIN. Distractors: heater band issue EIN L1 (8 Oct), hydraulic hose VAL L1 (15 Oct).

## Act 1 - "Today" (30 s)
Show the Genie space answering "Daily defect rate for EIN line 2 since 25 Oct". Message: good, but only structured data and the engineer still does the investigation.

## Act 2 - Interactive investigation in Teams (Copilot Studio)
For the simplest setup, follow the [one-incident ServiceNow guide](05_copilot_studio/copilot_studio_and_servicenow_notes.md).
Use the number generated by your colleague's ServiceNow instance in place of
INC0019874 below. The ticket description must retain the original scenario date,
site, line and equipment so the investigation matches the existing demo data.

1. "Start an RCA for INC0019874" (or the newly generated ticket number) -> Copilot Studio fetches the ticket from ServiceNow, calls the Foundry agent.
2. "When did the defects start and what is the last known good batch?"
3. "What changed on line 2 in the days before?" (expect: new lot 1187 + dryer dew point + deferred PM)
4. "Have we seen this before at any site?" (expect: INC0014211 / RCA-2025-014, INC0016502 / RCA-2026-007)
5. "Were the corrective actions from those RCAs implemented in Eindhoven?" (expect: no - LL-2025-06 tracker)
6. "What can we rule out?"

## Act 3 - Proactive (optional extension, not part of the one-incident setup)
Show the P1 trigger -> overnight draft RCA (TPL-RCA-002) in SharePoint -> Teams approval card to the Plant Manager -> on approval: ServiceNow work note + RCA reference, document to the RCA library -> next incident finds it.

## Act 4 - Value
Engineer hours per RCA (manual evidence collection across 5+ systems) x number of P1/P2 RCAs per year x sites; plus faster containment (here: the group-standard -30 C warning would have fired on 1 Nov 18:00 vs line stop 4 Nov 03:00 - ~2.5 days of scrap a proactive drift alert could have prevented).
